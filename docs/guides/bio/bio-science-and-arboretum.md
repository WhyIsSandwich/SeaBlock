# Bio Science and Arboretum

Bio progression often feels confusing because multiple systems unlock at once and each has setup prerequisites that are easy to miss.

## Read this if...

- You unlocked bio systems but cannot get a stable first loop.
- Arboretum/tree-related inputs are blocking progress.
- You want to avoid overbuilding bio before it pays off.

## Problem

Players reach a point where bio chains seem available, but required ingredients, trees, or intermediate loops are not yet practical to sustain.

## Readiness checks

Before scaling bio systems:

1. Core power and base metals are stable.
2. You have space and logistics for a pilot bio block.
3. You know exactly which science/material blocker bio is meant to solve.
4. You can keep a reserve of scarce bio inputs.

## Milestones

1. **Pre-bio prep:** stable base metals, circuits, and power.
2. **Arboretum readiness:** confirm required inputs and expansion room.
3. **First bio loops:** keep throughput modest and stable.
4. **Science integration:** route bio outputs into current science goals before scaling.

## Decision table

| Situation | Recommended action | Why |
| --- | --- | --- |
| Bio is unlocked but power is unstable | Delay bio scale and stabilize base first | Bio loops amplify instability |
| Arboretum inputs are inconsistent | Build reserve-first policy before expansion | Prevents stop-start cycle |
| One bio output blocks progression | Build smallest viable chain for that output only | Faster unlock path |
| Bio feels overwhelming | Pilot one loop end-to-end, then duplicate | Reduces complexity shock |

## Failure signatures

| Symptom | Likely cause | First fix |
| --- | --- | --- |
| Bio chain keeps stalling | Missing reserve policy for key inputs | Add minimum buffer levels before scaling |
| Large bio build under-delivers | Scaled before first stable pilot | Downscale, stabilize pilot, then grow |
| Arboretum path blocks all progress | Incorrect prerequisite assumptions | Validate required inputs/techs in current run |

## 2.0 notes

- If old guides describe older tree/bio assumptions, verify against current 2.0 chain behavior.
- Keep bio decisions tied to immediate milestone blockers rather than long-term megabase design.

## Build patterns

- Isolate early bio from your main bus until outputs are predictable.
- Use small pilot blocks to validate loops before committing space.
- Prefer clear input contracts (what must always be in stock) over perfect ratios.

## Common Mistakes

- Trying to fully optimize bio before first successful science integration.
- Assuming tree availability or placement without checking map constraints.
- Expanding bio chain count faster than supporting fluids and logistics.
